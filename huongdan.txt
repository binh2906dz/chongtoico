Docker Compose, 2 dịch vụ:
- app : 1 tiến trình Node 24 (Fastify) phục vụ API (/api/*), ảnh (/media/*),
        realtime Socket.IO (/socket.io) và giao diện React đã build (SPA).
        Khi khởi động: chạy migration Drizzle (server/drizzle/*.sql), tạo dữ
        liệu mặc định (chuyên mục, kênh chat), tạo admin từ ADMIN_USERNAME/
        ADMIN_PASSWORD nếu chưa có tên đó.
        Chỉ mở 127.0.0.1:APP_PORT (mặc định 8090).
- db  : PostgreSQL 17 (volume pgdata). Ảnh + video lưu ở volume uploads
        (/data/uploads; video ở /data/uploads/videos — TỐN Ổ CỨNG, theo dõi
        bằng `df -h` và `docker system df -v`).

Nginx cũ của VPS thêm site /etc/nginx/sites-available/chongtoico cho tên miền
phụ, proxy vào 127.0.0.1:APP_PORT (có header Upgrade cho websocket).
Hệ thống cũ (service "bot", Gunicorn 127.0.0.1:5000) không bị đụng tới.

1B) TELEGRAM BRIDGE (thư mục bot/ — dịch vụ riêng)
--------------------------------------------------------------------------------
Mô hình: **WEB giữ nội dung, BOT chỉ nhắc người dùng quay lại web**. Thành công
= người dùng MỞ WEB, không phải "gửi được tin nhắn".

Hai tiến trình độc lập:
- **web** (Fastify, 127.0.0.1:8090) — quyết định gửi cho ai / gửi gì / lúc nào;
  lưu notification_jobs, delivery_log, telegram_visits. **KHÔNG giữ token bot.**
- **bot** (Node.js + grammY, 127.0.0.1:8091 cho endpoint nội bộ) — giữ token
  Telegram của N bot, nhận /start /stop, gửi tin, health check getMe. **KHÔNG
  đụng DB của web**; chỉ giao tiếp qua HTTP API.

Xác thực 2 bên: header `X-Bot-Secret: <BOT_API_SECRET>` (biến môi trường chung,
KHÔNG commit). Mọi endpoint /api/bot/* so sánh bằng crypto.timingSafeEqual;
sai → 401.

Xác minh initData (web KHÔNG có token bot):
  web POST /api/telegram/miniapp/auth {initData}
    → gọi 127.0.0.1:8091/internal/verify (X-Bot-Secret)
      → bot verify HMAC bằng TẤT CẢ token → { ok, telegramId, username,
        firstName, authDate }
    → web kiểm tra authDate ≤ 24h → tạo/tìm user → set cookie 30 ngày.
  Endpoint nội bộ CHỈ bind 127.0.0.1. initData hết hạn / hỏng → trả thông báo
  "Phiên Telegram đã hết hạn, mở lại từ bot", KHÔNG tạo tài khoản.

Thư mục bot/ (package riêng, cài riêng — KHÔNG dùng chung node_modules):
- bot/src/config.ts    — biến môi trường, parse TELEGRAM_BOT_TOKENS
- bot/src/verifier.ts  — verify initData (thử mọi token, chống replay 24h)
- bot/src/internal-server.ts — POST /internal/verify (chỉ 127.0.0.1) và
                         POST /internal/check-bot (admin bấm "Kiểm tra" bot →
                         service bot chạy getMe thật, web chỉ ghi kết quả)
- bot/src/client.ts    — HTTP client gọi /api/bot/* (retry + backoff)
- bot/src/registry.ts  — nhiều bot: getMe → live/ban/error, chọn theo trọng số,
                         cooldown sau 429, heartbeat 5 phút
- bot/src/commands.ts  — /start [code], /stop, /help; 3 nút cố định
- bot/src/jobs.ts      — vòng lặp lấy job → gửi → báo kết quả; RateLimiter;
                         không gửi file media quá lớn / chỉ thành viên
- bot/src/index.ts     — logic (test được)   bot/src/main.ts — điểm vào chạy
- bot/test/bot.test.ts — 20 ca kiểm thử

Biến môi trường (xem .env.example):
  BOT_API_SECRET      — khoá chung web <-> bot (openssl rand -hex 32)
  BOT_INTERNAL_PORT   — cổng endpoint verify nội bộ (mặc định 8091)
  TELEGRAM_BOT_TOKENS — "<id>:<token>,<id>:<token>" (nhiều bot)
  SITE_URL            — URL công khai để dựng link trong tin nhắn
  ADMIN_CHAT_ID       — chat id nhận cảnh báo vận hành (tuỳ chọn)

Luật tần suất CỨNG do WEB thực thi (admin không vượt được):
  tối đa 1 tin/người/ngày · 3 tin/người/tuần · ≥6 giờ giữa hai tin
  chỉ gửi trong 08:00–22:00 giờ Việt Nam (ngoài khung → dời sang 08:00 hôm sau)
  bỏ qua: opt_out · notify_enabled=false · status=blocked · đã nhận cùng
  chiến dịch · đã nhận cùng nội dung trong 7 ngày (so hash text gốc)
  job status='sending' quá 10 phút → trả về 'queued' (bot chết không mất job)

Giới hạn media Telegram: ảnh ≤ 10 MB, video ≤ 50 MB. Media "chỉ thành viên"
KHÔNG gửi file (Telegram tải URL không có cookie → 403) → chỉ gửi link. Hệ thống
KHÔNG tự nén video.

Lệnh Telegram (chỉ 3, không menu bàn phím):
  /start        → nút "🌐 Mở Website" (+ "🔔 Nhận thông báo" / "🔕 Từ chối nhận")
  /start <code> → xác nhận liên kết tài khoản (mã 1 lần, hạn 15 phút, lưu sha256)
  /stop         → opt-out

API phía web (server/src/routes/telegram.ts):
  công khai : /api/telegram/entry · /miniapp/auth · /browser/register ·
              /link-code · /track · /optout-public
  bot      : /api/bot/register · /heartbeat · /jobs · /result · /start ·
              /link · /optout · /bots · /user/:telegramId · /stats
  admin    : /api/admin/telegram/overview · /users · /campaigns (+ send /
              activate / pause / cancel) · /articles/recent (kèm media[] thật) ·
              /import-ids · /imported-ids · /bots · /bots/:id/check
  Tất cả /api/bot/* kiểm tra header X-Bot-Secret (timingSafeEqual) → sai = 401.

GIAO DIỆN QUẢN TRỊ TELEGRAM (frontend/src/pages/admin/AdminTelegram.tsx,

KIỂM TRA BOT BỊ BAN (2026-11-25):
  - Server tự kiểm tra MỌI bot mỗi 24 giờ (server/src/botHealth.ts, chạy lần
    đầu sau 60s). Gọi getMe: sống -> status = live; 401 -> status = ban, ghi
    telegram_bot_incidents (chỉ ghi khi là ban MỚI), đặt banned_at +
    last_ban_reason; bot hồi sinh -> xoá incident cũ + banned_at = null.
  - Bot bị ban đã bị dịch vụ bot ngừng dùng từ trước (registry.markBanned).
  - Admin bấm "🔍 Kiểm tra bot" để kiểm tra ngay (POST
    /api/admin/telegram/bots/health-check). Danh sách sự cố: GET
    /api/admin/telegram/bots/incidents.
  - Bộ đếm giống bot_analytics cũ: telegram_bots.starts_count /
    interactions_count / replies_count / sent_count.

Giao diện người dùng: /tg/entry (Mini App), /tg/lien-ket (mã 1 lần + deep link),

3) BIẾN MÔI TRƯỜNG (.env — xem .env.example)
--------------------------------------------------------------------------------
- DOMAIN            : tên miền phụ (dùng cho Nginx/certbot trong install.sh)
- APP_PORT          : cổng nội bộ 127.0.0.1 (mặc định 8090; hệ thống cũ dùng 5000)
- POSTGRES_PASSWORD : mật khẩu DB (sinh ngẫu nhiên)
- ADMIN_USERNAME / ADMIN_PASSWORD : chỉ tạo tài khoản admin khi CHƯA có tên đó;
  đổi sau không đổi mật khẩu admin đã có (đổi trong trang cá nhân).
- COOKIE_SECURE     : true khi đã có HTTPS; false khi chạy http (nếu để true
  trên http thì trình duyệt không lưu cookie => không đăng nhập được)
- MAX_UPLOAD_MB     : dung lượng tối đa mỗi ảnh
- MAX_VIDEO_MB      : dung lượng tối đa mỗi video (mặc định 2048). Nginx site
  chongtoico cho /api/admin/articles tối đa 2100M — muốn lớn hơn phải sửa cả hai.
  Site Nginx tạo trước bản này (chưa có khối /api/admin/articles) => chỉ nhận
  200M; xoá /etc/nginx/sites-available/chongtoico rồi chạy lại install.sh,
  hoặc thêm khối đó bằng tay theo scripts/install.sh.
- TRUST_PROXY       : IP/dải mạng của proxy được tin để đọc X-Forwarded-For.
  Để trống = 127.0.0.1, ::1, 10/8, 172.16/12, 192.168/16 (Nginx trên VPS vào
  container qua Docker bridge 172.x). "false" = không tin proxy nào. TUYỆT ĐỐI
  không đặt tin mọi IP (trước 2026-11-08 là "true" => giả mạo IP được, vượt
  giới hạn đăng nhập).
- BOT_API_SECRET    : khoá dịch vụ chung giữa web và bot (X-Bot-Secret). Bắt
  buộc có khi dùng Telegram Bridge; sinh bằng `openssl rand -hex 32`.
- BOT_INTERNAL_PORT : cổng endpoint nội bộ xác minh initData (mặc định 8091,
  chỉ bind 127.0.0.1).
- TELEGRAM_BOT_TOKENS : "<id>:<token>,<id>:<token>" — token bot. CHỈ đặt cho
  service bot, KHÔNG đặt trong container web.
- TOKEN_ENCRYPTION_KEY : khoá mã hoá token bot lưu trong CSDL (AES-256-GCM).
  Bắt buộc khi muốn THÊM BOT TỪ TRANG QUẢN TRỊ; không có nó thì nút "Thêm bot"
  báo lỗi. Sinh bằng `openssl rand -hex 32`. KHÔNG commit.
- ALLOW_RESTORE       : đặt "1" để cho phép khôi phục CSDL từ trang quản trị.
  Mặc định "0" (chặn) để tránh hỏng dữ liệu. Bật khi thao tác, tắt lại sau.
- SITE_URL          : URL công khai của website (dựng link trong tin nhắn Telegram).
- ADMIN_CHAT_ID     : chat id Telegram nhận cảnh báo vận hành (tuỳ chọn).
