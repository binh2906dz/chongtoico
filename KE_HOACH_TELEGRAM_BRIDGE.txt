--------------------------------------------------------------------------------
1. BỐI CẢNH
--------------------------------------------------------------------------------

Hệ thống mới `chongtoico` là một CỘNG ĐỒNG WEB (diễn đàn, bài viết đa phương
tiện, chat, CSKH), xây theo mẫu shiperx.net nhưng có thương hiệu riêng "Chống
Tối Cổ" và nội dung hợp pháp.

Hệ thống cũ `telegram-bot-dashboard` là một BẢNG ĐIỀU KHIỂN VẬN HÀNH TELEGRAM
BOT (broadcast, quản lý bot, quản lý ID Telegram, bàn phím bot, sao lưu).

Mô hình mới đảo ngược vai trò:

  |                | Mô hình cũ               | Mô hình mới              |
  |----------------|-------------------------|--------------------------|
  | Trung tâm      | BOT (bot chứa nội dung) | WEB (web chứa nội dung)  |
  | Bot làm gì     | Phát nội dung, quản lý  | NHẮC người dùng quay    |
  |                | ID, quản lý nội dung    | lại web                  |
  | Nội dung lưu ở| albums (SQLite của bot) | articles (PostgreSQL web)|
  | Người dùng tương tác | Mini App → trang bridge → view album | Trực tiếp trên web |
  | Thành công =   | Gửi được tin nhắn      | NGƯỜI DÙNG MỞ WEB      |

Hệ quả: phần lớn chức năng quản trị nội dung của repo cũ trở nên vô nghĩa (nội
dung do web quản lý). Cái cần chuyển KHÔNG PHẢI "chức năng", mà là CƠ CHẾ ĐO LƯỜNG
VÀ NHẮC NHỞ.

2. CÁC QUYẾT ĐỊNH ĐÃ CHỐT (do chủ dự án — không cần hỏi lại)
--------------------------------------------------------------------------------

Q1  Mở bằng Mini App trong Telegram → TỰ TẠO TÀI KHOẢN (không hỏi mật khẩu),
    đăng nhập tức thì.
Q2  Mở bằng trình duyệt ngoài → BẮT BUỘC TẠO TÀI KHOẢN (username + mật khẩu).
Q3  Sau khi tạo tài khoản (cả 2 đường) → LIÊN KẾT VỚI TELEGRAM bằng lệnh /start
    gửi tới 1 bot NGẪU NHIÊN trong các bot đang hoạt động.
Q4  Bot dùng stack nào TIỆN, ÍT RỦI RO, KHỚP HỆ THỐNG MỚI → Python, service
    riêng, chỉ giao tiếp qua API web.
Q5  Admin TỰ CHỌN NỘI DUNG muốn gửi (không tự động chọn hộ) — kể cả chọn ẢNH
    HOẶC VIDEO kèm.
Q6  GIỮ NHIỀU BOT để tránh bị ban; có trọng số phân phối + tự tạm dừng bot lỗi.
Q7  Tài khoản ĐÃ ĐĂNG NHẬP (dù đường nào) → ĐƯỢC XEM nội dung "chỉ thành viên"
    ngay.
Q8  Tên hiển thị lấy từ TELEGRAM (first_name).
Q9  DIGEST ĐỊNH KỲ DO ADMIN QUẢN LÝ (bật/tạm dừng thủ công), không tự bật.
Q10 /start CHỈ HIỆN NÚT TRUY CẬP WEB (không có menu bàn phím, không có flow
    node).

3. QUYẾT ĐỊNH KIẾN TRÚC
--------------------------------------------------------------------------------

3.1 Bot làm bằng gì → PYTHON, SERVICE RIÊNG, CHỈ GIAO TIẾP QUA API

  | Phương án                                        | Rủi ro | Công sức | Khớp hệ thống mới? |
  |--------------------------------------------------|--------|----------|--------------------|
  | A. Python (giữ code bot cũ, tách ra service riêng) | Thấp   | Thấp     | Tách biệt hoàn toàn |
  | B. Node/grammY                                    | Cao    | Cao      | Đẹp hơn, 1 stack   |

  CHỌN A. Lý do:
  - Logic broadcast cũ đã xử lý 429 theo từng bot, giới hạn 25 msg/s, multipart
    upload, Forbidden → đánh dấu blocked — TÀI SẢN QUÝ, đừng viết lại.
  - Bot là SERVICE RIÊNG → lỗi bot không kéo web chết (đúng tinh thần N3/N4).
  - 2 stack trên 1 VPS là chấp nhận được; đổi lại: rủi ro thấp, lên nhanh.
  - Nếu sau này muốn gộp sang Node → dễ, vì giao tiếp qua HTTP API, không phụ
    thuộc DB.

3.2 Ranh giới trách nhiệm (bắt buộc)

  ┌──────────────── WEB (chongtoico, Node) ────────────────────────┐
  │ • Quyết định: gửi cho ai, gửi gì, lúc nào                     │
  │ • Lưu: notification_jobs, delivery_log, telegram_visits        │
  │ • KHÔNG giữ token Telegram (xem Mục 8 — verify initData)       │
  └───────▲───────────────────────────────┬────────────────────────┘
          │ GET  /api/bot/jobs            │ POST /api/bot/result
          │ POST /api/bot/heartbeat       │ POST /api/bot/link
          │ GET  /api/bot/link-code       │ POST /api/bot/start
          │ POST /api/bot/optout          │ POST /api/bot/register
  ┌───────┴───────────────────────────────▼────────────────────────┐
  │ BOT (service riêng, Python)                                     │
  │ • Giữ token Telegram của N bot                                  │
  │ • Gửi tin, nhận /start, health check getMe, chọn bot ngẫu nhiên  │
  │ • KHÔNG đụng DB PostgreSQL của web                              │
  └─────────────────────────────────────────────────────────────────┘

  Xác thực giữa 2 bên: header `X-Bot-Secret: <BOT_API_SECRET>` (biến môi trường
  chung, KHÔNG commit). Mọi endpoint /api/bot/* kiểm tra header này bằng
  crypto.timingSafeEqual; sai → 401.

5.2 Bảng mới

-- 1) Người Telegram (KHÁC HOÀN TOÀN với bảng users của web)
CREATE TABLE telegram_users (
  id                bigserial PRIMARY KEY,
  telegram_id      bigint NOT NULL UNIQUE,
  username         text,
  first_name       text,
  age_verified_at  timestamptz,
  captcha_ok       boolean NOT NULL DEFAULT false,
  opt_out          boolean NOT NULL DEFAULT false,      -- đã bấm "Từ chối nhận"
  opted_out_at     timestamptz,
  notify_enabled   boolean NOT NULL DEFAULT true,       -- nút "Nhận thông báo"
  status           text NOT NULL DEFAULT 'unknown',      -- unknown|active|blocked|invalid
  last_bot_id      text,
  created_at       timestamptz NOT NULL DEFAULT now(),
  updated_at       timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX telegram_users_status_idx ON telegram_users(status);
CREATE INDEX telegram_users_optout_idx ON telegram_users(opt_out);

-- 2) Người Telegram đã /start với bot nào
CREATE TABLE telegram_user_links (
  telegram_id bigint NOT NULL REFERENCES telegram_users(id) ON DELETE CASCADE,
  bot_id      text NOT NULL,
  started_at  timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (telegram_id, bot_id)
);
CREATE INDEX telegram_user_links_bot_idx ON telegram_user_links(bot_id);

-- 3) NỐI Telegram ↔ tài khoản WEB (bảng then chốt)
CREATE TABLE telegram_links (
  telegram_id  bigint NOT NULL PRIMARY KEY REFERENCES telegram_users(id) ON DELETE CASCADE,
  user_id      integer REFERENCES users(id) ON DELETE SET NULL,  -- NULL = chưa đăng nhập web
  method       text NOT NULL DEFAULT 'unknown',  -- miniapp|browser|code
  linked_at    timestamptz NOT NULL DEFAULT now(),
  last_seen_at timestamptz
);
CREATE INDEX telegram_links_user_idx ON telegram_links(user_id);

-- 4) Lịch sử gửi — CHỐNG GỬI TRÙM (đã có ở repo cũ, mang sang)
CREATE TABLE delivery_log (
  campaign_id  text NOT NULL,
  telegram_id  bigint NOT NULL,
  bot_id       text,
  status       text NOT NULL DEFAULT 'sent',  -- sent|failed|blocked|skipped
  error        text,
  sent_at      timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (campaign_id, telegram_id)
);
CREATE INDEX delivery_log_user_idx ON delivery_log(telegram_id);
CREATE INDEX delivery_log_sent_idx ON delivery_log(sent_at);

-- 5) Lần truy cập web từ Telegram — ĐO HIỆU QUẢ
CREATE TABLE telegram_visits (
  id          bigserial PRIMARY KEY,
  telegram_id bigint,
  user_id     integer,
  campaign_id text,
  article_id  integer,
  ref         text,     -- 'bot' | 'miniapp' | 'campaign' | 'start'
  src         text,     -- nguồn cụ thể: 'start' | 'campaign' | 'push'
  path        text,
  visited_at  timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX telegram_visits_camp_idx ON telegram_visits(campaign_id);
CREATE INDEX telegram_visits_user_idx ON telegram_visits(telegram_id);
CREATE INDEX telegram_visits_time_idx ON telegram_visits(visited_at);

-- 6) HÀNG ĐỢI GỬI (web quyết định, bot thực thi)
CREATE TABLE notification_jobs (
  id           bigserial PRIMARY KEY,
  campaign_id  text NOT NULL,
  telegram_id  bigint NOT NULL,
  bot_id       text,                 -- NULL = bot tự chọn bot sống
  payload      jsonb NOT NULL,       -- {text, buttons[], webUrl, media{}}
  status       text NOT NULL DEFAULT 'queued',  -- queued|sending|sent|failed|skipped|cancelled
  attempts     integer NOT NULL DEFAULT 0,
  scheduled_at timestamptz NOT NULL DEFAULT now(),
  sent_at      timestamptz,
  error        text,
  created_at   timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX notification_jobs_pick_idx ON notification_jobs(status, scheduled_at);
CREATE INDEX notification_jobs_camp_idx ON notification_jobs(campaign_id);

-- 7) BOT (chỉ metadata, KHÔNG lưu token ở web)
CREATE TABLE telegram_bots (
  id             text PRIMARY KEY,
  username       text,
  display_name   text,
  status         text NOT NULL DEFAULT 'unknown',  -- live|ban|error|unknown
  auto_responder boolean NOT NULL DEFAULT true,
  weight         integer NOT NULL DEFAULT 1,   -- trọng số phân phối
  sent_count     integer NOT NULL DEFAULT 0,
  blocked_count  integer NOT NULL DEFAULT 0,
  last_checked_at timestamptz,
  last_error     text,
  sort_order     integer NOT NULL DEFAULT 0
);

-- 8) MÃ LIÊN KẾT MỘT LẦN
CREATE TABLE telegram_link_codes (
  code_hash    text PRIMARY KEY,     -- sha256(code) — KHÔNG lưu code thô
  user_id      integer NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  bot_id       text NOT NULL,
  expires_at   timestamptz NOT NULL,
  used_at      timestamptz,
  created_at   timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX telegram_link_codes_exp_idx ON telegram_link_codes(expires_at);

-- 9) CHIẾN DỊCH (nội dung do admin soạn)
CREATE TABLE telegram_campaigns (
  id              text PRIMARY KEY,        -- uuid
  name            text NOT NULL,
  text            text NOT NULL DEFAULT '',
  media_type      text,                    -- image|video|none
  media_key       text,                    -- fileKey trong media/
  media_source    text,                    -- article_id | upload
  media_note      text,                    -- ghi chú cho admin
  buttons         jsonb NOT NULL DEFAULT '[]',
  target_type     text NOT NULL,           -- all_linked|visited|stalled|status|ids
  target_ids      jsonb NOT NULL DEFAULT '[]',
  schedule        text NOT NULL DEFAULT 'now',      -- now|at|daily|weekly
  schedule_status text NOT NULL DEFAULT 'paused',  -- paused|active|done
  scheduled_at    timestamptz,
  hour            integer NOT NULL DEFAULT 8,       -- giờ VN
  minute          integer NOT NULL DEFAULT 0,
  day_of_week     integer,                           -- 0=CN..6=T7 (weekly)
  status          text NOT NULL DEFAULT 'draft',    -- draft|queued|sending|done|cancelled|paused
  total           integer NOT NULL DEFAULT 0,
  sent_count      integer NOT NULL DEFAULT 0,
  failed_count    integer NOT NULL DEFAULT 0,
  click_count     integer NOT NULL DEFAULT 0,
  created_by      integer REFERENCES users(id),
  created_at      timestamptz NOT NULL DEFAULT now(),
  updated_at      timestamptz NOT NULL DEFAULT now()
);

5.3 Cột mới cần thêm vào bảng users

ALTER TABLE users ADD COLUMN telegram_id bigint;

6. GIAI ĐOẠN 1 — API WEB
--------------------------------------------------------------------------------

File mới: server/src/routes/telegram.ts (đăng ký trong server/src/app.ts cạnh
route khác).

6.1 Nhóm công khai (chưa đăng nhập)

  GET  /api/telegram/entry
       Điểm vào Mini App. Nhận initData (Telegram WebApp SDK tự truyền).
       Trả { mode: "miniapp"|"browser", botUsername?, needsAccount }
  POST /api/telegram/miniapp/auth
       Body { initData }. Verify → TỰ TẠO TÀI KHOẢN (tên từ Telegram) → set
       cookie phiên → trả { user, linked, linkRequired }
  POST /api/telegram/browser/register
       Body { username, password, displayName? } → tạo tài khoản thường →
       trả { user, linkRequired: true, linkUrl, code }
  GET  /api/telegram/link-code
       (đã đăng nhập) trả { code, botUsername, deepLink, expiresAt } — CODE MỚI
       MỖI LẦN GỌI, hạn 15 phút
  POST /api/telegram/track
       Body { campaignId?, articleId?, path?, ref?, src? } → ghi telegram_visits
  POST /api/telegram/optout-public
       Body { tid, cid } → đặt opt_out=true (nút "Từ chối nhận" trên web)

6.2 Nhóm bot (header X-Bot-Secret bắt buộc)

  POST /api/bot/register
       Body { botId, username, displayName } — bot tự đăng ký khi khởi động
       (ghi đè telegram_bots)
  POST /api/bot/heartbeat
       Body { botId, status, users?: [...] } — báo trạng thái + số người đã /start
  GET  /api/bot/jobs?limit=50
       Lấy job đến hạn. Trả [{ jobId, campaignId, telegramId, payload }], tự
       đánh dấu status='sending'
  POST /api/bot/result
       Body { jobId, status: sent|failed|blocked|skipped, error?, botId } → cập
       nhật job + ghi delivery_log
  POST /api/bot/start
       Body { telegramId, botId, username?, firstName?, code? } — bot báo "user
       đã /start"
  POST /api/bot/link
       Body { code, telegramId, botId, username?, firstName? } — xác nhận liên kết
  POST /api/bot/optout
       Body { telegramId, botId } — đánh dấu opt-out
  GET  /api/bot/bots
       Danh sách bot live (bot dùng để chọn ngẫu nhiên)
  GET  /api/bot/user/:telegramId
       Trạng thái 1 user (đã liên kết chưa, opt-out chưa)
  GET  /api/bot/stats
       Số liệu tổng quá cho dashboard bot

6.3 Nhóm admin (dùng requireAdmin)

  GET   /api/admin/telegram/overview
        Tổng quan: số người TG, đã liên kết, active/blocked, opt-out, CTR
  GET   /api/admin/telegram/users?page=&q=&status=
        Danh sách người Telegram + trạng thái
  PATCH /api/admin/telegram/users/:telegramId
        Đổi trạng thái (active/blocked/invalid), bật/tắt opt-out thủ công
  GET   /api/admin/telegram/campaigns
        Danh sách chiến dịch
  POST  /api/admin/telegram/campaigns
        Tạo chiến dịch (Mục 9)
  POST  /api/admin/telegram/campaigns/:id/send
        Đẩy job vào hàng đợi (tôn trọng luật tần suất)
  POST  /api/admin/telegram/campaigns/:id/activate
        Bật lịch (schedule_status='active')
  POST  /api/admin/telegram/campaigns/:id/pause
        Tạm dừng (schedule_status='paused')
  POST  /api/admin/telegram/campaigns/:id/cancel

8. GIAI ĐOẠN 3 — XỬ LÝ initData
--------------------------------------------------------------------------------

8.1 Vấn đề
initData được Telegram ký bằng BOT TOKEN:
secret_key = HMAC_SHA256(bot_token, "WebAppData"). Muốn web tự verify thì web
PHẢI CÓ TOKEN BOT → vi phạm nguyên tắc "token chỉ ở bot".

8.2 Khuyến nghị: WEB GỌI NỘI BỘ SERVICE BOT ĐỂ VERIFY

  Web (POST /api/telegram/miniapp/auth, body {initData})
    └─► gọi nội bộ 127.0.0.1:<BOT_INTERNAL_PORT>/verify  (X-Bot-Secret)
          └─► Bot verify HMAC bằng TẤT CẢ token → trả
              { ok, telegramId, username, firstName, authDate }
    └─► Web kiểm tra authDate ≤ 24h → tạo/tìm user → set cookie

  Ưu điểp: token không bao giờ nằm trong web. Web chỉ giữ BOT_API_SECRET.
  Phương án dự phòng: web lưu token bot MÃ HÓA (AES-256-GCM, khóa trong env),
  chỉ dùng để verify initData, KHÔNG dùng để gửi. Phải ghi rõ rủi ro trong LUAT
  mục 6.

8.3 Logic verify — tái dùng nguyên văn từ repo cũ

3 hàm trong app.py repo cũ (chất lượng tốt, đã đọc):
  - _parse_init_data_for_hash_check() — parse 1 lần
  - _validate_telegram_init_data() — HMAC-SHA256 + so sánh hash
  - _init_data_matches_any_bot_token() — thử MỌI token bot (đúng yêu cầu multi-bot)

Cải tiến bắt buộc so với repo cũ: cache danh sách token trong RAM 5 phút (repo cũ
đọc DB mỗi request → chậm).

  | initData hỏng / hết hạn                            | Trả "Phiên Telegram đã hết hạn, mở lại từ bot" — KHÔNG tạo tài khoản |
  | initData hợp lệ nhưng tài khoản đã có telegram_id khác | Không cho đổi → "Tài khoản đã liên kết với Telegram khác" |
  | Người tạo tài khoản ở trình duyệt, sau đó mở Mini App | Tìm theo telegram_id → chưa có → hỏi "Bạn đã có tài khoản? Đăng nhập để liên kết" → sau khi đăng nhập gọi /link-code |
  | Code liên kết hết hạn / đã dùng                     | Lỗi rõ ràng, cho tạo code mới              |
  | Bot bị Telegram ban (getMe → 401)                   | telegram_bots.status='ban', không chọn bot này, báo admin |
  | Tất cả bot đều ban/error                            | Không gửi gì; ghi log; báo admin; campaign → paused |
  | Telegram trả 429                                    | Bot dừng đúng retry_after; các bot khác chạy tiếp |
  | Telegram trả 403 Forbidden                           | telegram_users.status='blocked', không gửi lại, delivery_log.status='blocked' |
  | Bot bị giới hạn spam (429 kéo dài)                  | Tự giảm tần suất toàn hệ thống 24h, cảnh báo admin |
  | Job đã lấy nhưng bot chết trước khi gửi             | status='sending' quá 10 phút → trả về queued |
  | Web restart khi đang chạy chiến dịch                | Job nằm trong DB → không mất; cron tiếp tục |
  | Người nhấn "Từ chối nhận" trên web                   | Cũng đặt opt_out=true (tìm telegram_id qua telegram_links) |
  | 2 tab Mini App mở cùng lúc                         | INSERT ... ON CONFLICT DO NOTHING trên telegram_links.telegram_id |
  | Admin tạo chiến dịch daily nhưng quên bấm "Kích hoạt" | schedule_status='paused' → KHÔNG tự gửi (Q9) |
  | Video >50MB được chọn                               | Admin phải chọn "gửi link" hoặc "ảnh bìa kèm link" — hệ thống không tự nén |
